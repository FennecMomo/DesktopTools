# DesktopTools 自由窗口

一个常驻 Windows 系统托盘、可管理多个半透明置顶浮窗的桌面工具。

## 使用

Windows 可直接双击 `dist/DesktopTools.exe` 启动，无需安装 Python。使用源码时，双击 `start_overlay.cmd` 启动，也可以直接双击 `overlay_window.pyw`（需要已安装 Python）。

程序启动后会在任务栏右下角通知区域显示托盘图标。右键托盘图标可选择：

- **添加自由窗口**：绿色加号，在当前后台进程中创建一个新的独立窗口实例。
- **设置**：蓝色齿轮，统一调整全部实例的透明度、边缘收起开关、无背景显示和展开边距，也可设置当前用户开机启动。
- **检查更新**：从 GitHub 的版本索引检查并下载最新 EXE。
- **退出**：红色电源键，关闭全部自由窗口并结束后台程序。

双击托盘图标也可以快速添加一个自由窗口。

- 拖动顶部标题栏可移动窗口。
- 将标题栏拖到任意显示器边缘并松开，窗口会动画收起为置顶小球。
- 单击小球即可恢复；窗口会完整回到当前显示器内，并与停靠边保持 10px 间距。
- 拖动右下角可调整窗口大小。
- 点击“锁定”后，正文仍保持可见，但背景、标题和其他控件会隐藏；鼠标操作穿透正文到后方应用，悬浮也不会重新显示背景。
- 锁定时只有独立置顶的解锁图标可点击，点击后在原位恢复完整窗口。
- 点击窗口右上角“×”只关闭当前自由窗口实例。
- 开启设置中的“无背景”后，鼠标不在窗口上时只显示白字黑描边的正文，背景、标题、按钮和缩放手柄全部隐藏；鼠标移入窗口范围内会自动恢复完整界面。锁定时也使用同样的正文样式，在深色和浅色环境下都更容易辨认。

标题栏的“用途”按钮可为当前自由窗口选择四种模式：

- **便签**：随手记录临时文字，适合对照资料或整理思路。
- **待办**：添加事项，双击或点击“完成 / 撤销”切换状态；选中后可编辑或删除。编辑时在上方输入框修改，再按回车或点“保存修改”；“取消”会放弃改动。列表中也可按 F2 编辑、按 Delete 删除。
- **倒计时**：设置 1–180 分钟，可开始、暂停、继续和重置。
- **时钟**：始终置顶显示当前时间和日期。

每个窗口可以选择不同用途；切换模式不会清除该窗口的便签、待办或正在运行的倒计时。窗口的用途、位置和大小、便签文字、待办事项及其完成状态、倒计时设定的分钟数都会自动保存。退出程序后再次启动，会恢复退出时仍打开的窗口；点“×”关闭的窗口也会保留存档，下次从托盘“添加自由窗口”会优先恢复最近关闭的窗口。倒计时的运行进度不会跨重启延续，恢复后从设定时长重新开始。

在“无背景”或锁定状态下，空便签也会显示“空便签”提示，避免窗口看起来完全消失。

边缘收起支持多显示器，也支持位于主显示器左侧或上方的负坐标屏幕。

关闭最后一个自由窗口后，程序仍会在系统托盘中运行。只有托盘菜单中的“退出”会彻底结束程序。

全局设置保存在 `%LOCALAPPDATA%\DesktopTools\settings.json`，各窗口存档保存在同目录的 `windows.json`。修改后会自动写入磁盘，关闭窗口和退出程序时也会立即保存；写入时使用临时文件原子替换，避免中断损坏原文件。窗口以小球收起时的状态和位置、锁定状态同样会恢复；恢复锁定窗口时，独立解锁图标仍可点击。便签与待办内容是本机明文文件，请勿在其中记录密码等敏感信息。

“开机启动”默认关闭。开启后会在当前用户的 Windows `Run` 注册表项中记录程序路径，无需管理员权限；关闭或恢复默认设置会移除此项。建议先把 EXE 放在固定位置再开启；如果之后移动了 EXE，从新位置手动运行一次会更新已启用的启动项。

设置窗口也有“检查更新”按钮和“自动更新”开关。自动更新默认关闭；开启后，打包版 EXE 每次启动会在后台检查一次。新版来自仓库 `main/dist/update.json` 指向的 `dist/DesktopTools.exe`，下载后会校验文件大小和 SHA-256；校验通过才会准备安装。手动检查时可选择立即退出、安装并重新启动；否则会在下次正常退出程序后安装，下次启动即为新版。更新程序本身不使用本机的 Git 凭据，也不会覆盖便签、待办及设置存档。源码运行时不会自我更新，请改用 EXE 测试此功能。

## 版本与发布

版本号采用 `A.B.C`，首个版本为 `1.0.0`。今后**每次提交**按变更类型递增对应数字：系统框架或不兼容架构调整递增 `A`，新增或扩展功能模块递增 `B`，修复与一般修改（包括文档、界面细节）递增 `C`；递增较高位时，右侧数字归零。同一次提交涉及多类变更时取最高级别。提交时同步修改 `overlay_window.pyw` 中的 `APP_VERSION`，用 `python build_release.py` 重新打包并生成匹配的 `dist/update.json`，把源码、EXE 和索引一起提交。推送 `main` 后，用户端才会看见新版本。发布版本再建立同号的附注标签 `vA.B.C` 并推送；仓库的 GitHub Actions 会核对版本、大小及 SHA-256，再将 EXE 和索引作为 GitHub Release 附件发布，标签说明会作为发布说明。GitHub Actions 使用 GitHub 自带的临时令牌，本机无需保存 GitHub API 令牌。

程序只使用 Python 标准库，不安装依赖，托盘菜单图标也由程序直接绘制，无需额外图片资源。
